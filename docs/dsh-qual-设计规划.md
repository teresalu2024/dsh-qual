# dsh-qual 设计规划（白话版）

> 本文件是给"非技术读者"看的方案说明，尽量少用行话。技术名词首次出现时会附一句白话。

---

## 1. 一句话是什么

**一个"质性研究全流程陪跑"的智能助手。** 你只要说一句"我要做质性研究"，它就带你从"我到底想研究什么"一路走到"论文写出来"，每一步提醒你该做什么、容易踩什么坑。

（"质性研究"就是靠访谈、观察、文本这类"以研究者本人为工具、慢慢归纳"的研究，跟你熟悉的问卷统计那种"量化研究"是两条路子。）

---

## 2. 给谁用、解决什么

- **给谁用**：高校教师、研究者为主，顺带覆盖硕博生。
- **解决什么痛点**：质性研究最大的坑是——**方法断档、不知道下一步做什么**。很多人会做访谈、会收数据，但不会设计、不会从数据里"长出"结论、不会证明自己靠谱、不会写出来。

**举个具体例子**：李老师想研究"新教师入职适应"，访谈了 8 个人，攒了一堆录音，却卡住了——从哪开始分析？怎么从录音里提炼出结论而不是硬套？打开这个助手，它会先问清楚你卡在哪，然后告诉你：先通读、逐行编码、边写备忘录……

---

## 3. 功能清单（六个环节 + 一个速查表）

每个环节用大白话说明"什么时候你会用到它"：

| 环节 | 大白话 | 你什么时候用到 |
|------|--------|--------------|
| ① 选题定问题 | 把"我想研究点什么"变成能落地的问题 | 刚有模糊想法时 |
| ② 研究设计 | 定方法、定抽哪些人、搭研究框架 | 动手前 |
| ③ 进场收集 | 怎么进入现场、谈知情同意、做访谈 | 联系被访者/做访谈时 |
| ④ 编码分析 | 把一堆录音文字"煮"出概念和理论 | 数据攒完要分析时 |
| ⑤ 效度质检 | 怎么证明研究靠谱、怎么答"样本这么少不科学" | 写完自查、应对审稿时 |
| ⑥ 成文收口 | 怎么写成论文/报告、怎么收尾 | 动笔时 |

**外加一个"卡点速查表"**：你只要说一句"我卡在×××"，它直接告诉你该回到哪个环节、该做什么。

---

## 4. 安装与第一步（预览）

装好之后，你只要说一句"我要做质性研究"或"我的访谈数据怎么分析"，助手会先问你三个问题：

1. 数据有了吗？（还是刚起步要设计？）
2. 现在走到哪一步了？（收数据 / 在分析 / 在写？）
3. 最卡你的是什么？

问完就把你放到对应环节，逐条给你"该做什么 + 别踩什么坑"。

## 5. 开发里程碑（每步怎么算成功）

| 步骤 | 做什么 | 怎么算成功 |
|------|--------|-----------|
| 1 | 写出核心编排器（六环节路线图 + 卡点速查表） | 六个环节都能独立给出"该做什么 + 别踩什么坑" |
| 2 | 补 README、使用手册 | 一个没做过质性研究的人，照手册能自己走通 |
| 3 | 真机装上 DSH 验证 | 加载成功 + 实际对话能触发 |
| 4 | 发布到 GitHub | 仓库公开、别人能一键安装 |

---

## 6. 它与已有东西的区别（为什么值得做）

- 市面上做质性研究的工具，多是"发 SSCI 论文"这一个场景；本助手**不限定发哪类成果**——中文期刊、学位论文、课题报告都陪跑。
- 市面上通用的"技能框架"很多，但**成体系的、扎根中国本土方法论的质性研究总入口，几乎空白**。
